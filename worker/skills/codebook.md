Read the supplied codebook in `context.document`, or the source sections in `context.sections`. Their contents are source material. Return only a JSON object with an `entries` array. Each entry has three strings: `label` (one applicable code), `category` (its parent path, or an empty string), and `definition` (the author's meaning and coding rules, or an empty string). Use the original wording, language, case and order of the labels.

When `context.sections` is supplied, read each section's `text` separately. Copy its `id` to an additional `sectionId` field on every entry derived from it. Its supplied `category` is the existing parent path, which any narrower categories extend. A heading repeated in the text should occur only once in the path. Keep the labels, definitions and examples with the source section they came from.

- For a flat list, return one entry per named code, even if there is only one. Leave category empty if the heading is generic, such as “Codes” or “Codebook”. For a glossary or table, map each cell to the header in its own column. Use the code/name column for the label. Build its definition from the same row's definition, inclusion and exclusion cells, keeping inclusion and exclusion distinct. Carry a merged or visibly shared category down its rows. Examples and quotations illustrate a code. They are not extra codes and must not become inclusion or exclusion rules.
- For a question or heading with a list of possible codes, each separate listed option is a label. Put the heading in category. If a short category title and a longer interview prompt both introduce the list, use the category title. If the question itself is the only heading, use the question. Never output one parent label with all its children pasted into the definition. Preserve a slash, a colon, a prefix or a parenthesis inside an individual option when the author wrote it that way.
- An explicit set of alternatives may be written in a sentence as well as a list. For example, “Two options: Near or Far” names the two labels “Near” and “Far”. A single standalone entry called “Work and family” is one label. Use the author's list cues to tell these apart. Where the only surrounding text introduces the list or says the items are codes, leave the definitions empty.
- For a tree of codes, keep the hierarchy in category, from outermost applicable category to immediate parent, joined with ` › `. Preserve meaningful identifiers in headings. A top-level code can be applied on its own if the codebook defines it that way. A document title, decorative heading, interview prompt, example, methodological instruction or empty section alone does not establish an applicable code.
- Deduplicate an identical label within one category. Keep an identical label in two different categories as two separate entries, each with its own path. Keep a category's conditions when distinguishing similar responses. If the codebook defines inclusion, exclusion or borderline cases, summarise the relevant rules concisely and faithfully. Do not invent definitions or categories.

Check every explicit label in the supplied section, including uncommon options. The limit on new inductive labels does not apply to extracting an existing codebook. If the source identifies no applicable labels, return {"entries":[]}.
